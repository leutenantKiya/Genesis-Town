# Islands phase 1a + 1b Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Buy a Private Island from the broker (NFT `IS-<id>-1` minted via the broker), upgrade Kesuburan Tanah off chain, Save World to swap it for `IS-<id>-2`; travel between the Public Island and your island; see other players live with chat bubbles.

**Architecture:** Contract v5 adds an `islands` map and two voucher-checked methods (`buy_island`, `save_island`). The server signs vouchers, keeps island state and upgrades off chain, checks positions per world, and streams presence + chat over SSE. The client swaps the outdoor world between the village and an island generated from the island's seed.

**Tech Stack:** Rust near-sdk 5.29 (unit tests with `testing_env!`), Node 24 TypeScript (`node --test`, `node:sqlite`, near-api-js 7.4), plain-JS client mods on `window.GT`.

**Spec:** `docs/superpowers/specs/2026-11-06-islands-design.md` (read it first). Codebase map: `CLAUDE.md`.

## Global Constraints

- Token id format `IS-<id>-<version>`, `<id>` u32 ≥ 1, version starts at 1. Only the current version may have a balance.
- Never two versions of one island held at once: `save_island` burns `IS-<id>-<v>` and mints `IS-<id>-<v+1>` in one call.
- Island purchase coin is moved buyer → broker, then burned from the broker in the same call.
- Save World writes only upgrades whose cost ledger rows are already settled (`ledger.settled = 1`).
- Island methods take zero deposit (session keys sign them, the relayer pays gas).
- Private Islands have no merchants, no Pasar, no Permata.
- Chat: max 80 characters, ≤ 1 message per 2 s per account, last 50 per world kept in memory only, never on chain.
- Display names: 3–16 chars, `[A-Za-z0-9 _-]`, unique case-insensitive.
- In-game text is Indonesian; code, comments, commits English. Commit messages: one plain sentence of what the player gets, no `feat:` prefix, ending with the `Co-Authored-By` line given by the orchestrator.
- No new npm dependencies on the server or client. The contract may add the dev-dependency `ed25519-dalek = "2"` for tests only.
- Nothing is deployed to testnet by agents (the owner deploys v5 with their own key).
- Do not edit `prototype/`.

## Pinned interfaces (shared by all tasks)

**Voucher messages** (UTF-8 bytes, signed with plain ed25519 over the bytes, no hashing; signature sent base64):

```
GT-ISLAND-BUY|{contract_id}|{island_id}|{buyer}|{price}|{seed}|{size_level}|{fertility_level}|{expires_ns}
GT-ISLAND-SAVE|{contract_id}|{island_id}|{owner}|{from_version}|{seed}|{size_level}|{fertility_level}|{expires_ns}
```

All numbers in decimal, no padding. `expires_ns` = block timestamp limit in nanoseconds (server uses now + 10 min).

**Contract methods (v5):**
- `buy_island(island_id: u32, spec: IslandSpec, price: U128, expires_ns: U64, signature: Base64VecU8)`
- `save_island(island_id: u32, from_version: u32, spec: IslandSpec, expires_ns: U64, signature: Base64VecU8)`
- `get_island(island_id: u32) -> Option<IslandView>`
- owner: `set_voucher_key(public_key: PublicKey)`, `set_broker(broker_id: AccountId)`
- `migrate(broker_id: AccountId, voucher_key: PublicKey, new_tokens: Vec<TokenMeta>)` (from v4 state)
- `IslandSpec { seed: u32, size_level: u8, fertility_level: u8 }` (json + borsh)
- `IslandView { island_id: u32, token_id: String, owner_id: AccountId, version: u32, spec: IslandSpec }`
- game event (standard `genesis-town`): `island` with `{what: "bought"|"saved", island_id, version, account}`

**Server HTTP (all signed like `/api/act`):**
- `GET /api/islands` → `{ offers: OfferView[], mine: IslandState[] }`
  - `OfferView { island_id, name, spec: IslandSpec, price }`
  - `IslandState { island_id, token_id, version, saved: IslandSpec, live: IslandSpec, savable: IslandSpec, pending: Array<{attr, level, waitingSettlement: boolean}>, invite: string[] }`
- `POST /api/islands/voucher {kind: "buy"|"save", island_id}` → `{ method: "buy_island"|"save_island", args: {...exact contract args...} }`; the client passes `method` and `args` to its existing `signedCall` → `/api/relay`.
- `POST /api/act` gains an optional `world: "public" | "IS-<id>"` (default `"public"`) and the actions `travel {to}` and `island_upgrade {island_id, attr: "fertility"}`.
- `GET /api/islands/layout?island_id=N` → `{ seed, spec }` (the client builds the map with `GTIsland.generate`).
- Presence: `GET /api/stream?world=<id>` (SSE, same auth as `/api/state`), events `presence` `{players: [{account, name, x, y, dir, scene}]}` ~2×/s and `chat` `{account, name, text, t}`; `POST /api/chat {world, text}`; `POST /api/name {name}`; `GET /api/state` gains `name` (null until chosen).

**Shared client API:**
- `window.GTIsland.generate(seed: number, spec: {size_level, fertility_level}) -> Layout` in `client/js/world/island.js` (same `Layout` shape as `GTVillage.generate`: `w, h, chunk, tiles, chunks, unlocked, buildings (own house has own:true), market.stalls (empty), farm.plots, spawn`, plus `dock: {x, y}`). 32 × 32, one open chunk `{id: "island", name: "Pulau Pribadi"}`. Plots: size_level 1 → 6, 2 → 9, 3 → 12.
- Public Island dock: `GTVillage.dockOf(layout) -> {x, y}`: the walkable shore tile next to water closest to the plaza, computed after generation without touching the RNG or any tile (existing maps must not change).
- Engine: `GT.worldId() -> "public" | "IS-<id>"`, `GT.switchWorld(id, layout)`.

**Economy config** (`economy/config.json`, new top-level `islands`):
```json
"islands": {
  "broker": "makelar",
  "offers": [{ "island_id": 1, "name": "Pulau Kelapa", "seed": 7101, "size_level": 1, "fertility_level": 1, "price": 0 }],
  "upgrades": { "fertility": [ { "level": 2, "cost": { "wood": 0, "coin": 0 } } ] },
  "fertility": [ { "level": 1, "growFactor": 1, "yieldBonus": 0 } ]
}
```
8 offers; prices from the simulator (Task B1). Fertility levels 4–5 cost `permata`; while `permata` is not in `items` they are returned with `locked: true`.

## Review Focus

1. A voucher reused after a successful buy, or for another buyer/island/price → contract rejects; server never issues a buy voucher for an owned island.
2. Save World pressed right after an upgrade bought today → savable spec excludes it; the UI says "lunas setelah settlement 06:00".
3. A player reports a position on an island they don't own and aren't invited to → 409, nothing happens.
4. Server restart → island ownership is re-read from chain (`get_island` for every offer id), not trusted from SQLite.
5. Chat flood / 81-char message / HTML in chat → rejected or escaped; bubble never injects HTML.
